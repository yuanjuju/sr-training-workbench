# 目录与内容组织约定

## 每层负责什么

| 目录 | 内容 | 组织依据 |
| --- | --- | --- |
| `studies/` | 每项实验的目标、方法、结果与证据入口 | 研究问题及具体运行 |
| `scripts/` | 数据、环境、预检、训练、评估工具 | 工作流职责 |
| `configs/` | SAFMN / CAMixerSR 的训练与测试 YAML | 模型与用途 |
| `results/` | 指标、原始日志、配置快照、验证记录和图片 | 测量来源及运行归属 |
| `learning/` | 教学脚本、环境说明和精选推理样例 | 学习主题 |
| `docs/` | 详细实验报告、方法和解释 | 文档主题 |
| `patches/` | 上游兼容修改 | 对应上游项目 |
| `third_party/` | 第三方许可文本 | 来源 |

## 新增一项实验

1. 在 `studies/<研究问题>/README.md` 写清问题、固定条件、唯一变量、评价口径和验收条件。
2. 将可维护配置放到 `configs/<模型>/train/` 或 `test/`，将工具放到对应 `scripts/` 子目录。
3. 为新运行建立独立结果目录，将日志、实际配置、环境、指标和核验记录关联到该运行。
4. 在实验入口和 `results/README.md` 添加结果链接，详细说明可放在 `docs/`。
5. 在首页展示核心结论，并链接到完整记录。

## 历史证据的路径

原始 `results/safmn_fft_pair_30k/` 是云端 suite 的归档快照，保留其既有层级，包括内部的 `configs/` 和 `results/`。其中的绝对路径描述当时的云端环境。
归档脚本与 `scripts/` 中的可维护版本各有用途，来源哈希对应实际运行的归档版本。

工作流脚本按功能重新分类后，仓库路径与云端部署路径可能不同。例如训练管理器仍读取云端 suite 根目录中的评估脚本；部署位置见 [工具索引](../scripts/README.md)。

## 按内容提交

- 每个提交围绕一个可说明的主题，例如数据检查、训练控制、一次实验结果或学习样例。
- 工具和配置移动时，同一提交更新命令、导入路径及文档链接。
- 新结果提交包含方法标签、指标来源、对应图和结果说明。
- 二进制权重、训练数据、环境与本机临时输出由 `.gitignore` 管理；精选图明确放到公开结果或样例目录。

当前已发布的历史提交保留。此次结构整理以新的内容提交完成。
